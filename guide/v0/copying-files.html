Copying Files

Upload and download

  • Upload… in the MicroVM's header copies files from this Mac into the MicroVM's home folder: dev's in the starter image, or root's with Run as root. A file already there is never overwritten: the copy is numbered, such as report (1).pdf.
  • Drag and drop files onto the terminal to upload them the same way.
  • Download… shows the MicroVM's files, starting in the home folder. Double-click a folder to open it, or use Home, /workspace and the up arrow; choose a file and press Download…, then say where to save it on this Mac. A path you already know, such as ~/out.txt, can be typed instead. A folder with more than 2,000 items shows the first 2,000.

Files always go to the home folder, even with a persistent /workspace; move them there with mv. The terminal doesn't need to be connected, and it stays usable while a file copies.

Limits

  • At most 100 MB per file, either way.
  • Folders can't be copied. Zip them first: zip -r project.zip project in the MicroVM, or Compress in the Finder.
  • One transfer at a time per MicroVM, while it's running. Resume a suspended one first.
  • A transfer stops if the MicroVM doesn't answer for 60 seconds.

Cancel stops a transfer. A file part-way through an upload isn't kept, and a cancelled download saves nothing. In a batch, the files already copied stay, and the result lists them.

Files to copy at launch

A workspace's Files to copy go from this Mac into each new MicroVM the first time it connects. They go to the home folder there, except config files such as ~/.gitconfig and ~/.ssh/config, which keep their place. They're limited to 1 MB in total, and copied once per MicroVM: later edits on this Mac don't reach a MicroVM that already has them.
